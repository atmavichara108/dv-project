## 2. Dev mode — что это и как соотносится с вайбкодингом

### Что такое dev mode

**Dev mode** (режим разработки) — это способ запуска приложения на твоей локальной машине для разработки и тестирования.

В `package.json` есть два варианта:

**Вариант 1: Hot reload (основной для вайбкодинга)**
```bash
npm run dev
```
Это запускает `tsx watch src/server.ts` — сервер стартует напрямую из TypeScript кода, и **автоматически перезагружается** при любом изменении файлов.

**Вариант 2: Production-like (проверка перед деплоем)**
```bash
npm run build && npm start
```
Это сначала компилирует TypeScript в JavaScript (`vite build`), потом запускает скомпилированный код (`node dist/server.js`). Это то, что будет работать на сервере.

### Как это соотносится с вайбкодингом

**Вайбкодинг** — это когда ты описываешь изменения на естественном языке, а AI пишет код. Dev mode с hot reload идеально подходит для этого:

1. Ты запускаешь `npm run dev` в терминале
2. Открываешь браузер на `http://localhost:8787`
3. Говоришь AI: "Добавь кнопку на главную страницу"
4. AI меняет код
5. `tsx watch` видит изменение, перезапускает сервер (1-2 секунды)
6. Ты обновляешь страницу в браузере, видишь результат
7. Если не нравится — говоришь AI что исправить, цикл повторяется

**Почему это важно:**
- Без hot reload тебе пришлось бы каждый раз вручную останавливать сервер и запускать заново
- С hot reload ты видишь изменения почти мгновенно
- Это ускоряет итерации: описал → увидел → скорректировал → увидел

### Когда использовать каждый режим

| Режим | Команда | Когда использовать |
|---|---|---|
| Hot reload | `npm run dev` | Вайбкодинг, разработка новых фич, отладка |
| Production-like | `npm run build && npm start` | Проверка перед деплоем, тестирование производительности |
| Production (сервер) | `pm2 start` | На сервере, после деплоя |

## 3. Деплой — как сделать

### Что такое деплой

**Деплой** — это перенос кода с твоей локальной машины на сервер, где он будет доступен пользователям.

### Как работает скрипт деплоя

Скрипт `scripts/deploy-vps.sh` делает следующее:

**Шаг 1: Сборка локально**
```bash
npm run build
```
Компилирует TypeScript в JavaScript, создаёт папку `dist/` с готовым кодом.

**Шаг 2: Синхронизация файлов на сервер**
```bash
rsync -avz --delete dist/ dv@re-search.wiki:/opt/dv-hub/dist/
rsync -avz --delete public/ dv@re-search.wiki:/opt/dv-hub/public/
rsync -avz package.json package-lock.json dv@re-search.wiki:/opt/dv-hub/
```
Копирует скомпилированный код, статические файлы и package.json на сервер.

**Шаг 3: Установка зависимостей и перезапуск на сервере**
```bash
ssh dv@re-search.wiki
cd /opt/dv-hub
npm ci --omit=dev
pm2 restart dvhub || pm2 start ecosystem.config.cjs
pm2 save
```
Подключается к серверу, устанавливает production-зависимости, перезапускает приложение через PM2.

### Как запустить деплой

```bash
npm run deploy:vps
# или
bash scripts/deploy-vps.sh
```

### Что нужно перед первым деплоем

**На сервере нужно:**

1. **Создать директорию `/opt/dv-hub`:**
   ```bash
   sudo mkdir -p /opt/dv-hub
   sudo chown dv:dv /opt/dv-hub
   ```

2. **Создать `.env` файл с секретами:**
   ```bash
   nano /opt/dv-hub/.env
   # Вставить все переменные из примера выше
   ```

3. **Инициализировать базу данных:**
   ```bash
   cd /opt/dv-hub
   node scripts/init-db.js
   ```

4. **Настроить PM2:**
   ```bash
   pm2 start ecosystem.config.cjs
   pm2 save
   pm2 startup
   ```

### Нужен ли infra агент для деплоя?

**Для первого деплоя — да.** Infra агент поможет:
- Создать директорию `/opt/dv-hub`
- Настроить `.env` файл
- Инициализировать базу данных
- Настроить PM2
- Проверить что всё работает

**Для последующих деплоев — нет.** Достаточно запустить `npm run deploy:vps` с локальной машины.
